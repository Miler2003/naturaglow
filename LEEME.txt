 COMO FUNCIONAN LOS ROLES
 ------------------------
 Al entrar, sesion.js decide a donde va cada quien:

   admin / empleado  ->  panel.html    (gestion de productos)
   cliente           ->  inicio.html   (la portada)

 Eso esta en la funcion Sesion.destino(). Ademas, panel.html revisa la
 sesion al abrirse: si entra alguien que no es personal, lo devuelve al
 login. Y dentro del panel los dos roles NO son iguales:

   admin     puede crear, editar y ELIMINAR productos
   empleado  puede crear y editar; el boton Eliminar le sale desactivado


 LO QUE YA FUNCIONA
 ------------------
 - Acceso con dos pestanas (entrar / crear cuenta) y validaciones
 - Deteccion de rol y redireccion segun quien entra
 - Cuentas de clienta guardadas en el navegador
 - Portada completa: heroe, destacados, historia, pie
 - Catalogo con filtro por categoria y orden por nombre o precio
 - Ficha de producto con selector de cantidad y relacionados
 - Carrito: sumar, restar, quitar, subtotales, envio y total
 - El contador del encabezado sobrevive al recargar y al cambiar de pagina
 - La barra de arriba se encoge y le sale sombra al bajar
 - Pago simulado: tarjeta dibujada que se llena sola, validacion del
   numero con el algoritmo de Luhn, vencimiento, CVV y datos de envio;
   pantalla de "procesando" y confirmacion con numero de pedido
 - Panel del personal con el CRUD completo sobre los productos, cifras
   del inventario y permisos distintos por rol
 - Lo que el panel cambia se ve de inmediato en el catalogo
 - Diseno adaptable a telefono

 COMO PROBAR EL PAGO
 -------------------
 Hay tres formas de pagar y cada una se valida distinto:

 TARJETA
 Numero de prueba:  4111 1111 1111 1111
 Vencimiento: cualquiera futuro (ej. 09/29)    CVV: 3 digitos

 Si pones otro numero, el formulario lo rechaza: la funcion luhn()
 aplica el mismo algoritmo que usan los bancos para saber si un numero
 esta bien escrito.

 YAPE / PLIN
 Sale la imagen del codigo QR, el numero 941 252 892 y el monto.
 Debajo hay un recuadro: "Ya hiciste el pago?" con el boton
 "Si, ya pague". Al tocarlo el recuadro se pone verde y dice
 "Pago realizado"; recien ahi el boton Pagar deja terminar el pedido.
 Si se intenta pagar sin confirmar, el recuadro se pone rojo.

 Los QR son provisionales (dicen "pega aqui tu codigo QR"): reemplaza
 img/qr-yape.jpg y img/qr-plin.jpg por los tuyos, cuadrados.

 En los tres casos hacen falta los datos de envio completos y un
 telefono de 9 digitos.

 COMO CONECTARLO A LA BASE DE DATOS REAL
 ---------------------------------------
 Todo el contacto con el exterior esta en js/datos.js, en el objeto API.
 Hoy devuelve datos de muestra. Para conectar:

 1. En la VM de aplicacion (20.104.234.86), crear la carpeta y el endpoint:

      sudo mkdir -p /var/www/html/api
      sudo nano /var/www/html/api/productos.php

    Contenido:

      <?php
      require '../config.php';
      header('Content-Type: application/json; charset=utf-8');
      $sql = "SELECT id_producto AS id, id_categoria AS categoria, nombre,
                     descripcion, precio, stock, es_organico AS organico
              FROM productos";
      $res = $conexion->query($sql);
      $salida = [];
      while ($f = $res->fetch_assoc()) {
          $f['precio']   = (float)$f['precio'];
          $f['stock']    = (int)$f['stock'];
          $f['organico'] = ($f['organico'] === 'si');
          $f['envase']   = 'botella';   // columna a agregar en la tabla
          $f['insignia'] = '';
          $salida[] = $f;
      }
      echo json_encode($salida, JSON_UNESCAPED_UNICODE);

 2. Lo mismo con api/categorias.php sobre la tabla categorias.

 3. En js/datos.js cambiar:

      BD_ACTIVA: false     ->     BD_ACTIVA: true

    Y nada mas. El resto del front no se toca.

 4. Para el panel hacen falta ademas tres endpoints de escritura, que ya
    estan llamados en datos.js:

      api/producto_crear.php        ->  INSERT INTO productos ...
      api/producto_actualizar.php   ->  UPDATE productos SET ... WHERE id
      api/producto_eliminar.php     ->  DELETE FROM productos WHERE id

    Mientras tanto, el objeto Almacen de datos.js hace de base de datos
    guardando la lista en el navegador. Por eso el CRUD ya funciona de
    verdad aunque la VM no este conectada.

 OJO: al abrir el HTML desde la laptop (file://) y pedir datos a otra
 direccion, el navegador bloquea la peticion por CORS. Hay dos salidas:
   a) subir tambien el front a /var/www/html de la VM, o
   b) agregar en los .php:  header('Access-Control-Allow-Origin: *');
